# Crypto Pulse

A stateless, static-first crypto editorial platform — weekly and daily market reports generated by an agent pipeline, published via Next.js, and delivered to subscribers through Beehiiv. No database. No auth. No subscriptions. The complexity is in the content pipeline, not the infrastructure.

**Live site:** [weekly-crypto-pulse.com](https://weekly-crypto-pulse.com)

---

## What this is

Crypto Pulse is a weekly crypto market newsletter and web platform. Every Monday, an LLM-driven agent pipeline researches live market data, writes a plainspoken editorial report, runs it through a multi-stage editorial review, and commits the result as a static JSON artifact. The Next.js site reads those artifacts at build time and renders them as static pages.

The paid tier (Pro Pack) is a deeper decision-support document generated offline by a CLI tool and delivered to buyers by email. Stripe is the sole source of buyer identity — there is no user account system, no entitlement database, and no runtime payment validation on any page.

This is a portfolio project that demonstrates an unusual combination: sophisticated content generation (multi-agent LLM pipeline with editorial review, schema validation, and retry logic) on top of a deliberately simple infrastructure stack (static files, no database, no auth).

---

## What's architecturally interesting

**Stateless content pipeline.** Every report is a JSON artifact committed to the repo. The website has zero runtime dependencies beyond the files it was built with. Vercel builds the site; the pipeline commits data; nothing coordinates them at runtime.

**Multi-agent editorial pipeline.** A Daily Researcher fetches live data (CoinGecko, DeFiLlama, RSS feeds). A Daily Writer transforms it into a plainspoken artifact via LLM. A Daily Editor runs a 15-item editorial checklist — also via LLM — and either approves or sends specific revision notes back to the writer. The pipeline retries up to three rounds before auto-approving with a logged issue list.

**LLM provider abstraction with automatic failover.** GitHub Models is the primary LLM provider (free tier, fast). Anthropic Claude is the fallback. The client is a thin abstraction layer that switches transparently — neither the writer nor the editor knows which provider answered.

**Build-time chart generation.** The weekly reports include market snapshot trend and regime history charts. These are rendered as SVG server-side (using a pure-JS SVG renderer, no browser required), then converted to PNG via `sharp` for the Pro Pack. The Recharts components on the web pages use the same underlying data.

**Per-artifact OG images.** Every report page gets a programmatically generated Open Graph image via Next.js's image generation API, built at request time using the report's metadata.

**Schema-versioned artifacts.** Report artifacts carry an explicit `schemaVersion` field (`weekly@1.3`, `daily@1.2`). The validator rejects artifacts that don't match the expected schema, preventing silently broken deployments.

## Tech stack

- **Framework:** Next.js 16 (App Router, static export)
- **Rendering:** React 19, Tailwind CSS v4, Recharts (interactive charts on weekly pages)
- **Charts (server-side):** Custom SVG renderer + `sharp` for PNG export
- **LLM:** GitHub Models (primary), Anthropic Claude Sonnet 4.6 (fallback)
- **Email:** Beehiiv (subscriber management + broadcast delivery)
- **Payments:** Stripe (Payment Links — no checkout SDK, no webhooks)
- **Deployment:** Vercel (static pages + serverless API routes for subscription forms)
- **CI:** GitHub Actions (daily pipeline, weekly pipeline, CodeQL, smoke e2e via Playwright)
- **Testing:** Vitest (unit + integration), Playwright (smoke e2e)
- **Language:** TypeScript 6, strict mode

## How to run locally

```bash
git clone https://github.com/castanhf/Weekly-Crypto-Pulse.git
cd Weekly-Crypto-Pulse
npm install
```

Copy the environment template and fill in what you need:

```bash
cp .env.example .env.local
```

Required env vars for local development:

| Variable | Purpose |
|---|---|
| `GITHUB_TOKEN` | Primary LLM provider (GitHub Models). Use a personal access token. |
| `NEXT_PUBLIC_SITE_URL` | Canonical URL (e.g. `http://localhost:3000`) |

Optional (for specific features):

| Variable | Purpose |
|---|---|
| `ANTHROPIC_API_KEY` | LLM fallback if GitHub Models is unavailable |
| `BEEHIIV_API_KEY` + `BEEHIIV_PUBLICATION_ID` | Email subscription and broadcast |
| `STRIPE_PAYMENT_LINK_WEEKLY_PRO` + `STRIPE_PAYMENT_LINK_MONTHLY_BUNDLE` | Pro tier CTAs |

```bash
npm run dev          # Start the Next.js dev server
npm run test         # Run all unit + integration tests
npm run typecheck    # TypeScript strict check
npm run build        # Production build
```

The site will work without any env vars set — the report pages render from the static JSON artifacts in `data/reports/` and `data/dailies/`.

## Running the pipelines locally

```bash
# Generate a daily report
npm run generate:daily-input    # Step 1: research
npm run generate:daily-report   # Step 2: write
npm run review:daily-report     # Step 3: editorial review

# Or run the full daily pipeline in one command
npm run run:daily-pipeline

# Generate a Pro Pack for a specific weekly report
npm run generate:pro -- --product singleIssue --slug <report-slug>

# Generate a Pro Pack monthly bundle
npm run generate:pro -- --product monthlyBundle --month <YYYY-MM>
```

## Project structure

```
├── app/                     # Next.js App Router pages and API routes
│   ├── reports/[slug]/      # Weekly and daily report detail pages
│   └── pro/                 # Pro tier landing page
├── components/              # React components (charts, nav, paid block, etc.)
├── data/
│   ├── reports/             # Weekly report JSON artifacts (committed to repo)
│   ├── dailies/             # Daily report JSON artifacts (committed to repo)
│   └── pro-packs/           # Generated Pro Pack deliverables (git-ignored)
├── domain/                  # TypeScript types: Report, DailyArtifact, ProProduct, etc.
├── lib/
│   ├── charts/              # SVG renderer + PNG export (server-side, no browser)
│   ├── email/               # Beehiiv client + email composition
│   ├── llm/                 # LLM client with GitHub Models / Anthropic failover
│   ├── market-data/         # CoinGecko provider + data ingestion abstraction
│   ├── markets/             # DeFiLlama TVL client + asset category registry
│   ├── news/                # RSS aggregator (multi-source)
│   └── reports/             # Artifact repository, validator, distribution logic
├── scripts/                 # Pipeline scripts (research, write, review, generate)
├── .claude/agents/          # Agent specs for the LLM pipeline stages
├── e2e/                     # Playwright smoke tests
└── .github/workflows/       # GitHub Actions: daily pipeline, weekly pipeline, CI
```
