# Crypto Pulse v2.1.2 — R2.1.1 Maintenance & Stabilization

Released: 2026-05-20

This release is the closeout of R2.1.1, a maintenance and stabilization phase following the initial reader-visible launch (v2.1.0) and the dotenv CI hotfix (v2.1.1). R2.1.1 focused on editorial quality, observability infrastructure, dependency maintenance, and architectural discipline — no new reader-visible features were added.

---

## Editorial Quality

### Writer and editor agents upgraded to Anthropic Sonnet 4.6

The daily and weekly writer/editor agents now use Anthropic Sonnet 4.6 as their primary LLM (with GitHub Models gpt-4o-mini as fallback). The researcher continues on gpt-4o-mini (free tier, sufficient for catalyst curation).

Why: Empirical evidence from WCP-151 showed gpt-4o-mini had a quality ceiling for editorial voice that no prompt tuning could overcome. Specifically, ~40% of editor checks fired as false positives on otherwise-acceptable output, and the writer's iteration produced near-duplicate drafts rather than substantive revisions. Sonnet 4.6 produces editorial output indistinguishable from professional financial journalism, with first-round approval rates that justify the cost difference.

Estimated annual cost: ~$35–50/year at typical pipeline volume (auto-recharge enabled on Anthropic account).

### Editorial voice tuning

Writer and editor agent specs have been substantially tuned with both hard constraints (no advisory framing, no empty causal attribution, no "mixed results" filler) and editorial examples (story-first summaries, specific catalysts, proper attribution). The increase from 3 to 5 revision rounds, combined with stuck-loop detection and best-headline retention, ensures the pipeline iterates productively without burning tokens on repetitive output.

### Winners/losers logic redesign

The pre-existing >5% threshold rule has been replaced with top-N-by-percent-change selection:

- Daily reports surface exactly 1 winner + 1 loser
- Weekly reports surface 3+3
- Adaptive section labels: "Weakest gainers" replaces "Losers" on all-positive market days; "Smallest losses" replaces "Winners" on all-negative days

Schema versions bumped: daily@1.1 → 1.2, weekly@1.2 → 1.3. Backward compatibility preserved — existing artifacts continue to render correctly.

Reader-facing impact: every report now provides distribution context regardless of market volatility. On quiet days, the report shows the steepest gainer and steepest decliner; on all-positive days, the "loser" section adapts to show the weakest performer.

## Observability Infrastructure

### Component render testing

The test suite now exercises React components in a happy-dom environment using @testing-library/react. Component tests cover the winners/losers section (including adaptive labels), the paid block (Stripe payment integration UI), and the navigation header (active state logic).

### LLM client smoke test

New `npm run smoke:llm` validates both GitHub Models and Anthropic credentials in under 30 seconds without spending significant tokens. Useful for verifying environment configuration before deploys and during operational debugging.

### Bundle size baseline

`npm run build:analyze` produces detailed bundle composition reports. Current baseline (post-Tailwind v4 migration): 1.1 MB total, 11 chunks, largest chunk ~359 KB. Soft budgets documented at `docs/operations/bundle-size-baseline.md`.

### CodeQL enforcement

CodeQL workflow flipped from `continue-on-error: true` (set during R2.1 when GitHub Advanced Security wasn't enabled) to fail-on-error. GHAS now enabled at the repo level. Security findings block PR merges until addressed.

### Test coverage growth

R2.1.1 added 111 tests across 13+ new test files. Final count: 545 tests across 63 files. The growth reflects coverage for schema discipline, agent spec consistency, component rendering, and the new editorial logic.

## Maintenance

### Dependency upgrades

Four major version dependencies upgraded:

- **TypeScript 5.5.3 → 6.0.3** — one latent type issue surfaced and resolved (Buffer/Uint8Array generics in chart export)
- **React 18 → 19** — JSX namespace removal handled via single global ambient declaration
- **Tailwind v3.4.6 → v4.3.0** — config migrated to @theme directives, bundle size held steady

The ESLint 9 → 10 upgrade is deferred pending typescript-eslint releasing an ESLint-10-compatible version. The ecosystem blocker is documented; Dependabot PR #148 remains open and will be revisited when the dependency chain resolves.

### Beehiiv integration fixes

The Beehiiv integration shipped in WCP-136 had three production bugs that surfaced during R2.1.1 validation:

1. Broadcast endpoint was `/broadcasts` (deprecated) instead of `/posts`
2. Tag application required a separate API call after subscription, not inline
3. Error responses weren't surfacing response bodies, making debugging blind

All three fixed. Beehiiv-specific error handling now includes structured response body extraction. A smoke test (`npm run smoke:beehiiv`) validates connectivity and configuration without spending API quota.

### Email distribution architectural deferral

During R2.1.1 validation, Beehiiv returned 403 on the broadcast send endpoint. Investigation revealed Beehiiv's pricing structure: regular API access is available on all tiers, but the **Send API** (programmatic broadcast triggers) is restricted to Enterprise tier (custom pricing).

Architectural response (Option B1 minimal abstraction):

- Email distribution disabled via `BEEHIIV_BROADCAST_ENABLED=false`
- Pipeline orchestrators decoupled from any specific ESP via `lib/email/email-sender.ts` interface
- Beehiiv-specific code preserved at `lib/email/beehiiv-email-sender.ts` for future reuse
- `NoOpEmailSender` returns success silently when email is disabled
- Pipelines run cleanly with email off; content publishing is unaffected

Re-enabling email distribution requires either upgrading Beehiiv to Enterprise OR migrating to an alternative ESP. Full re-enablement checklist documented at `docs/operations/email-distribution.md`.

### Path alias enforcement extended

WCP-139's path alias convention (relative imports in script-consumed `lib/` directories) extended to cover `scripts/` directory. One file (`generate-market-data-snapshot.ts`) was found violating the convention and fixed. The convention test now scans both `lib/` and `scripts/`, preventing future drift.

### Schema bump discipline

The WCP-153 → WCP-154 cycle revealed that schema bumps require coordinated updates across multiple layers (domain constants, validators, repositories, agent specs, React components, tests). The 8-layer checklist at `docs/operations/schema-bumps.md` documents the human process. An automated test (`lib/reports/schema-bump-coverage.test.ts`) verifies each valid schema version is supported across all critical code paths.

### Editor spec deduplication completion

The editor agent's spec is split between markdown (rule descriptions in plain English) and TypeScript (structured check definitions and validation logic). WCP-152 introduced this approach; WCP-159 completed it with a consistency test (`lib/agents/editor-spec-consistency.test.ts`) that fails if the markdown spec and TypeScript check definitions drift.

### Email template polish

HTML email templates now include a hidden preheader `<span>` (drawn from the content summary) that controls the preview snippet shown in inbox clients, and the `<meta name="x-apple-disable-message-reformatting">` tag for Apple Mail compatibility. Deferred limitations (Outlook table layout, dark-mode media queries, unsubscribe handling) documented in `docs/operations/email-distribution.md`.

## Infrastructure

### Pipeline reliability

Multiple latent bugs eliminated:

- **Doubled execution:** Pipeline scripts had unguarded module-level `main()` calls, causing the researcher to run twice per cron (~$0.01 wasted per daily). Fixed via `require.main === module` guards on all entry points.
- **Log noise:** Pre-flight state checks logging as "Failed:" when they were just startup conditions. Fixed by restructuring orchestration.
- **Placeholder duplicates:** Orchestrator generated placeholder unconditionally at startup; both real and placeholder artifacts committed. Fixed to only generate placeholder on catastrophic pipeline failure.
- **Email-send failures:** Email send failures no longer fail the entire pipeline. Content publishing exits cleanly with WARNING on email failure (previously FATAL).
